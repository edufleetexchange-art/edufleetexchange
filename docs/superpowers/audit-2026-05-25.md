## CRITICAL (Severity 1) — block release

### Auth & onboarding

1. **`TeacherSignup.tsx:62-94`** — `signupTeacher()` is called fire-and-forget; `handleSubmit` is not `async`, has no `await`, no try/catch. Success toast and `navigate('/teacher/dashboard')` fire BEFORE the API completes. On failure, user is redirected anyway, `ProtectedRoute` bounces them to `/login`, then AuthContext's `toast.error` fires after navigation — confusing UX, possibly leaves stale form state.

2. **`Signup.tsx` → `AuthContext` `signup()` shim** — The back-compat institute signup path passes a hardcoded empty address `{street:'', city:'', state:'', pincode:''}`. The server requires non-empty `address.street/city/state/pincode`. **Institute self-signup will 400 every time** unless `Signup.tsx` is updated to collect address or to call `signupInstitute` directly with valid address.

3. **`AdminLogin.tsx:31-32`** — `login()` succeeds → immediately `navigate('/admin')` without checking `account.role`. Any user (teacher/institute) who navigates to `/admin/login` and provides valid credentials gets routed into the admin shell. `AdminLayout` shows "Access Denied" but the login page is the wrong place to discover that. Fix: assert `account.role === 'admin'` after login.

4. **`AdminLogin.tsx:122-138`** — Hardcoded demo credentials `admin@edufleet.com / admin123` and `institute@demo.com / password123` rendered in plain HTML — visible to any visitor, no dev-mode guard.

### Dashboards & flows

5. **`Dashboard.tsx:186-199` (institute create-listing)** — `subscriptionStats` is hardcoded `null` and `availablePlans` is `[]`. Result: `canAdvertise` is always `false`, `maxListings` is always `0`, `listingLimitReached` always `true`. Every institute hits "Listing Limit Reached" immediately. The entire create-listing flow is broken for all institute users.

6. **`Dashboard.tsx:570-573`** — Job Edit and Delete buttons on the institute dashboard have **no `onClick` handlers**. Clicking does nothing. Users cannot edit or delete their own job postings from the dashboard.

7. **`InstituteJobApplications.tsx:549`** (also `pages/InstituteJobApplications.tsx:595`) — `application.teacherName.charAt(0)` crashes if `teacherName` is null/undefined (Avatar fallback). Hard runtime error → white screen.

8. **`JobDetails.tsx:241,250`** — Accesses `job.salary.currency`, `.min`, `.max` directly. The `Job` type declares `salary` as `string | {…}`. If the API returns a string-typed salary (legacy data) or partial object, this throws → white screen. (`TeacherJobDetails.tsx` has a safe `formatSalary()` helper; `JobDetails.tsx` doesn't.)

9. **`TeacherJobDetails.tsx:122`** — `checkApplicationStatus` only compares `app.jobId === id` (string ===). If the backend populates `jobId` as an object, the comparison always returns false. **A teacher who already applied sees "Apply Now" again and can submit duplicate applications.** `JobDetails.tsx:93` correctly handles both string and populated-object cases.

### Cross-cutting

10. **`adService.ts:79,138`** — `MOCK_ADS` is referenced but never defined anywhere in the repo. On any API failure for `getAdsByPlacement` / `getAllAds`, the catch branch throws `ReferenceError: MOCK_ADS is not defined`. Ad placement breaks silently when the API is unreachable.

11. **`AdSlot.tsx:147-149`** — Unsanitized `dangerouslySetInnerHTML` on admin-created ad `htmlContent`. No DOMPurify or equivalent. **Stored-XSS vector** — a malicious approved HTML ad runs script in every user's browser.

## IMPORTANT (Severity 2) — degrades experience

### Auth & navigation

12. **`Header.tsx:69`** — `shouldShowInstituteNav = user?.role === 'institute' || (!user?.role && user)`. The second clause is truthy for any authenticated account with no/undefined role — leaks institute-specific nav links.

13. **`Header.tsx:229`** — Plan badge: `(subscription.planId as any).displayName`. `planId` is a string ID, not a populated object. The badge always shows raw plan ID like `64f8a1b2...` instead of a human name.

14. **`Login.tsx:43-45`** — Catch block sets a generic hardcoded message `'Invalid email or password. Please try again.'` regardless of actual error. Inactive account, network failure, server 500 — all show the same misleading message. Also fires a duplicate toast (AuthContext + page both call `toast.error`).

15. **`ProtectedRoute.tsx:22`** — Unauthenticated redirect to `/login` doesn't preserve `location.state.from`. Login then routes by role, ignoring the originally-intended destination → deep links never resolve correctly.

16. **`Landing.tsx:35`** — `useEffect` depends on `window.location.hash`. Non-reactive value; SPA hash-link clicks never trigger the scroll.

17. **`TeacherSignup.tsx:31` + `AuthContext.signupTeacher`** — Form sends `instituteSearchability` but the context normalizer reads `(input as any).isAvailable` instead. The teacher's discoverability preference set at signup is **silently dropped**.

### Dashboards

18. **`Dashboard.tsx:178` and `Dashboard.tsx:355-358`** — `stats.totalViews` and vendor "Profile Views" / "Contact Requests" use `Math.random()` per render. Numbers flicker on every re-render.

19. **`Dashboard.tsx:301` and `TeacherDashboard.tsx:207-210`** — `<SubscriptionAlert subscription={null} stats={null} />` — both dashboards hardcode `null` to the alert component despite having real `subscription` in scope. Quota alerts never fire on either dashboard.

20. **`Dashboard.tsx:88-101`** — `api.jobs.getApplications()` called with no args. Fetches all applications (or fails with 403) instead of scoping to the institute's own jobs. Errors silently swallowed (console.error only).

21. **`TeacherDashboard.tsx:100-107`** — `handleSaveProfile` only sends `name` and `phone` to `updateAccount`. Edits to `location`, `bio`, `experience`, `qualifications`, `subjects`, `isAvailable` are **silently dropped** while `toast.success('Profile updated successfully!')` fires. Acknowledged TODO at line 102 but UX still misleads. Need a profile-update endpoint OR remove non-savable fields from the edit form.

22. **`TeacherDashboard.tsx:515`** — `new Date(app.appliedDate).toLocaleDateString()` — backend may send `appliedAt`. Mismatched field name → "Invalid Date" displays.

23. **`TeacherSearch.tsx:103-112`** — `sendInterviewInvitation` collects date/time/message but **makes no API call**. Just a toast and a state reset. Institute interview invites are silently discarded.

### Cross-cutting

24. **`teacherService.ts:79`** — Calls `/users?role=teacher` (legacy endpoint) instead of `GET /api/teachers`. Server-side filtering by subject/experience/instituteSearchability is skipped; all filtering is done client-side after fetching everything.

25. **`crmService.ts:33-56`** — `getLeadActivities`, `createActivity`, `getMyTasks`, `createTask`, `updateTaskStatus` all call `apiClient` without `requiresAuth: true`. If apiClient doesn't auto-attach auth, every CRM operation 401s for authenticated users.

26. **`subscriptionEnforcement.ts:42-58,98-114`** — Mock fallback always returns `allowed: true` when the API errors. Server-side enforcement is the backstop, but **the UI silently passes any quota check on API failure** → no user warning about degraded state.

27. **`PricingSection.tsx:121`** — `plan.billingPeriod` access on a type without that field. Result: every plan is labeled `/yr` (the else branch fires unconditionally). Monthly plans are mislabeled.

28. **`UserManagement.tsx:447`** — Tab list is `grid-cols-6` but the `roles` array has 7 entries. The "Admins" tab overflows on every viewport.

29. **`UserManagement.tsx:517-519`** — `user.subscription` accessed directly on the raw `/admin/users` response. Subscription is now a separate collection — relies on undocumented backend population. If backend stops populating, all plan info shows "No Active Plan".

30. **`AuditLogManagement.tsx`** — `filters.endDate` is in state and sent to the service, but **no `<Input>` exists for it**. Date-range filtering silently doesn't work.

31. **`Dashboard.tsx:748`** — Listings table "Views" column is hardcoded to `245` for every row. No real view tracking.

32. **`SubscriptionUsageCard.tsx:85,125,152,179`** — `text-muted` class used instead of `text-muted-foreground`. The class doesn't exist in shadcn/Tailwind config — labels render invisible.

33. **`Header.tsx:229`** — Logo `<img>` uses `object-contain` inside a `rounded-full` clipping div. Transparent-edge logos appear undersized.

34. **`adService.ts`** — Silent mock fallback for `getAllAds` hides API failures from admins. Broken backend → admins see fake content thinking the system is working.

## Coverage gaps (missing flows)

59. **No edit/delete flow for jobs** despite buttons being rendered (see Critical 6).
60. **Duplicate codepaths:** `src/components/InstituteJobApplications.tsx` AND `src/pages/InstituteJobApplications.tsx` both define near-identical components; `JobApplicationsTab` is a third. Maintenance hazard.

## Confirmed working (positive findings)

- All 13 documented API endpoints respond with correct status codes (verified via curl smoke).
- `AuthContext` correctly hydrates `account/profile/subscription` after login/signup; logout clears state and storage.
- `authService.logout()` clears localStorage even on server failure (`finally` block).
- `JobDetails.tsx:93` correctly handles both string and populated-object `jobId` in `checkApplicationStatus`.
- `JobListingForm` has thorough field validation (experience cross-check, salary cross-check, multi-select for subjects/qualifications).
- `ListingForm` performs `checkListingLimit` on mount AND on submit, with `refreshSubscription` after create.
- `SubscriptionAlert` covers all six alert states (expired, expiring, browse limit, listing limit, suspended, pending payment) when given non-null data.
- `NotificationContext` mark-as-read is optimistically updated and double-decrement-safe.
- `MarketingDashboard` and `SalesDashboard` correctly use `useAuth().account` and check `account.role`.
- `AdminLayout` correctly gates by role (internal vs subscriber).
- `SupplierForm.category` is now driven by `useConfig()` — the previously flagged enum mismatch is mitigated.
- `MaskedContent` is null-safe and login-gated cleanly.

## Recommended next steps

Ordered roughly by leverage:

1. **Fix the 11 Critical bugs** — most are 1-line or small-file fixes (#1, #2, #5, #6, #7, #8, #9, #19 are quick; #10 needs to define `MOCK_ADS` or remove the fallback; #11 needs DOMPurify).
2. **Set up Playwright + write 6 golden-path E2Es** (one per persona) so the next refactor doesn't reintroduce these. Each test: signup → login → land on dashboard.
3. **Sweep the silent failures** — every place the code silently swallows API errors and shows a success toast (#23, #34, #44, etc.). These are the worst kind of bug because users believe an action succeeded.
4. **Resolve the duplicate codepaths** (#60) and consolidate `InstituteJobApplications` into one component.
5. **Add a teacher profile-update endpoint** (server-side gap) so #21 stops silently dropping data. Currently a documented TODO.
6. **Address the back-compat token shape (`responseData?.data || responseData`)** — pick one shape, type it, remove the OR fallback. Multiple subagents flagged this as fragile.
